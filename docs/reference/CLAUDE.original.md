# CLAUDE.md — 방꾸미 2.0 (바이브톤 전국대회) 작업 하네스

이 문서는 VS Code 내 Claude Code가 **방꾸미 2.0** 프로젝트를 일관되고 안전하게 개발하기 위해 반드시 지켜야 하는 최상위 지침(Harness)입니다.

---

## 1. 언어 및 소통 규칙
- 모든 답변, 설명, 코드 주석, 커밋 메시지, UI 텍스트는 **자연스러운 한국어**로 작성한다.
- 불필요한 서론 없이 핵심 변경사항과 검증 결과를 간결하게 보고한다.
- 추측하지 말고, 구현 후 반드시 `npm test`와 `npm run build`를 실행해 실제 통과 결과를 확인한 뒤 완료라고 보고한다.

---

## 2. 절대 불변 원칙 (Guardrails — 위반 금지)
1. **계산은 코드, 설명·추정은 AI:** 가구 좌표, 치수, 충돌, 문/서랍/의자 열림 공간, 통로 폭, 아이 안전 거리, 예산 합계는 **100% 순수 자바스크립트 코드**로 계산한다. AI(LLM)에게 좌표를 계산시키거나 점수를 매기게 하지 않는다.
2. **점수제 금지 → 3단계 전문가 피드백:** 100점 만점 점수제를 절대 만들지 않는다. 모든 배치 평가는 `(1) 확실한 문제(오류)`, `(2) 개선 제안(관습·안전 참고값)`, `(3) 취향별 테마 배치안(특징 이름)` 3단계로만 제공한다.
3. **벽/인접 가구 밀착 정상 허용:** 책상 옆 책장, 침대 옆 협탁·수납장 등 가구를 벽이나 다른 가구에 딱 붙이는 배치에 감점이나 경고를 띄우지 않는다. 오직 **가구와 가구 사이의 어정쩡한 5~50cm 데드스페이스**만 개선 제안으로 알린다.
4. **API 키 서버 완전 격리:** 모든 AI API 키는 Vercel 서버리스 함수(`/api/*`)의 서버 환경변수(`process.env.*`)에서만 읽는다. `VITE_` 접두사가 붙은 클라이언트 환경변수나 프론트엔드 번들에 API 키를 절대 넣지 않는다.
5. **무단 크롤링 금지:** 오늘의집, 다나와, 직방 등 외부 사이트의 페이지를 서버에서 자동으로 긁어오는(스크래핑/크롤링) 코드를 작성하지 않는다. 쇼핑몰은 공식 검색 링크 연결 + 사용자 직접 입력 + 사진/링크 AI 추정으로 처리한다.
6. **정직한 고지 문구 필수:**
   - 예상 가격: `"시연용 예상 가격"` 표시
   - 통로 60cm 및 아이 안전 기준: `"참고값 (법적·안전 기준 아님)"` 표시
   - AI 포토리얼 연출 이미지: `"AI 연출 이미지 (치수 참고용)"` 배지 표시
7. **시연 무중단 (Fallback 필수):** 모든 `/api/*` 호출은 15초 타임아웃과 실패 시 규칙 기반 기본 응답(Fallback)을 가져야 한다. 네트워크가 끊겨도 2D·3D·배치·비용 기능은 100% 정상 동작해야 한다.

## 3. 기술 스택 및 폴더 구조 규약
- **프론트엔드:** React 19 + Vite + Tailwind CSS + Three.js (지연 로딩)
- **모바일 앱:** Ionic Capacitor (`android/`, `ios/`) + PWA (`public/manifest.webmanifest`)
- **백엔드:** Vercel Serverless Functions (`api/*.js`)
- **데이터 규약:** 모든 모듈은 반드시 `SCHEMA.md`의 JSON 구조를 따른다. 임의로 필드명을 바꾸지 않는다.

```text
/
├── CLAUDE.md              # 최상위 작업 지침 (현재 파일)
├── SPEC.md                # 기능 명세 및 완료 기준
├── SCHEMA.md              # 공통 JSON 데이터 규약
├── api/                   # Vercel 서버리스 함수 (AI 호출 전용, 키 격리)
│   ├── advice.js          # 3단계 피드백 자연어 설명
│   ├── furniture.js       # 자연어/사진/링크 가구 치수·색상 추정
│   ├── style.js           # 커스텀 스타일 팔레트 생성
│   ├── floorplan.js       # 평면도 사진 → 방/문/창문 인식
│   └── render-photo.js    # 3D 캡처 → AI 포토리얼 연출 이미지
├── src/
│   ├── engine/            # 순수 JS 계산 모듈 (브라우저 의존성 금지, Node 테스트 가능)
│   │   ├── layout.js      # 5종 테마 배치 생성기
│   │   ├── validator.js   # 1단계 확실한 문제 + 2단계 관습·아이안전 피드백
│   │   └── cost.js        # 보유 가구 제외 예산·비용 계산
│   ├── components/        # UI 패널 (헤더, 방/가구/비용/리포트, 모바일 바텀시트)
│   ├── canvas2d/          # SVG 2D 평면도 (드래그, 8방향 리사이즈, 단축키, Undo/Redo)
│   ├── canvas3d/          # Three.js PBR 뷰어, 1인칭 걷기, 90cm 시선, 시간대 채광
│   ├── lib/               # API 클라이언트(VITE_API_BASE_URL 지원), 로컬 저장소(Capacitor 호환)
│   └── data/              # 기본 가구 카탈로그, 스타일 프리셋, 예시 방 데이터
├── tests/                 # node --test 단위 테스트 (엔진·비용·안전규칙)
└── public/                # 아이콘, 매니페스트, 경량 PBR 텍스처
```

## 4. 개발 및 자동 검증 워크플로 (TDD & Self-Check)
1. **엔진 우선 테스트:** `src/engine/` 코드를 작성하거나 수정할 때는 반드시 `tests/*.test.js`에 단위 테스트를 먼저 작성하고 `npm test`로 검증한다.
2. **기존 배치 보존 확인:** 가구 추가 로직을 수정할 때, 기존에 사용자가 수동으로 옮겨 둔 가구 좌표가 유지되는지 반드시 테스트한다.
3. **모바일/PC 반응형 확인:** 새 UI 컴포넌트를 만들 때 PC(1280px 이상)와 모바일(390×844) 레이아웃이 깨지지 않는지 확인한다.
4. **완료 전 필수 체크리스트:**
   - `npm test` 전체 통과
   - `npm run build` 오류 0건
   - 클라이언트 번들(`dist/`)에 API 키 문자열이나 개인 경로가 포함되지 않았는지 확인

## 5. 대회 현장 작업 팁 (Claude Code 운용)
- 새 기능을 시작하기 전 항상 `SPEC.md`와 `SCHEMA.md`를 먼저 읽고 작업한다.
- UI, 배치 엔진, 3D 뷰어, `/api/*` 서버리스 함수는 `SCHEMA.md`를 경계로 독립적으로 개발·테스트한다.
- 한 번에 모든 파일을 다 고치지 말고, **작은 단위 구현 → 테스트 → 확인** 루프를 유지한다.
