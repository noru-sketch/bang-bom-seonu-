# 작업지시서 4 · 공공 데이터

**목표**: "샘플이 아니라 **공개 데이터로 계속 갱신되는 서비스**"임을 보여 준다. 어떤 데이터를 어디서 받아 앱의 어느 부분에 쓰는지 지도를 만든다. 심사위원의 "실현 가능하냐" 질문에 대한 답이다.

## 찾을 데이터 (앱에서 쓰는 곳)
| 분야 | 데이터 후보 | 앱에서 쓰는 곳 |
|---|---|---|
| 미분양 현황 | 국토부 미분양주택현황(통계누리·KOSIS), 시군구별 준공 후 미분양 | 홈 숫자, 지도 구별 통계 |
| 시세 | 국토부 아파트 전월세 실거래가 API (공공데이터포털) | "시세 대비 ○% 낮음" |
| 건물 정보 | 건축물대장 API (준공일, 세대수, 층수) | "왜 이 집?" 준공 연도 |
| 임대 공고 | LH 공고 API / 마이홈 공공주택 정보 | 모집 상태·기간 자동 갱신 |
| 청년 정책 | 온통청년 청년정책 API | 정책 판정 규칙 갱신 |
| 전세사기 | HUG 전세보증금 반환보증 사고 현황, 대구 전세사기 피해자 결정 현황 | 발표 근거: "대구 전세사기 피해 ○건" ★ |
| 인프라 | 지하철역 위치, 병원 정보(심평원), 대형마트·영화관 위치 | 지도 시설 선 |
| 지도 | 행정경계(통계청), OpenStreetMap | 지도 바닥 (이미 사용 중) |

## 할 일
1. 위 데이터마다 **실제로 있는지, 받는 방법(파일/API), 인증키 필요 여부, 갱신 주기, 이용 조건(출처 표시 등)** 확인
2. 가능하면 **하나는 직접 받아 보기**: 공공데이터포털에서 대구 아파트 전월세 실거래가 API 키 신청 → 대구 달서구 최근 한 달 데이터 받아서 CSV 저장 (작업지시서 1·3에 넘기기)
3. **전세사기 숫자** 찾기: 대구 전세사기 피해 건수·금액, 다세대·빌라 비중 → "공공·리츠 임대 아파트는 왜 상대적으로 안전한가" 근거
4. 실서비스 구조 한 장: 데이터 → 방봄 서버(매일 갱신) → 판정·지도
