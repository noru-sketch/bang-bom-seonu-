## 1. 조사 목표
“공공 데이터가 있다”에서 끝내지 않고, 어떤 데이터를 어떤 방식으로 받아 앱의 어느 기능에 연결하는지와 현재 검증 상태를 구분한다.

## 3. 실제 서비스 데이터 흐름
공공 데이터/API·파일 → 수집 서버 → 단지명·주소·법정동·전용면적 표준화 → 기준일·출처 저장 → 미분양·시세 매칭 → 전세·월세·매매 추천 및 실부담 계산.

## 4. API 조회 방식
매매 실거래가는 지역코드와 계약년월을 조합해 조회한다. 전월세 실거래가는 법정동 코드 앞 5자리와 계약년월을 조합해 조회한다. 조회 결과에서 단지명·전용면적·층·가격·계약일을 정제하고 미분양 단지와 주소 또는 단지명으로 매칭한다.

## 5. 대구 적용 순서
1) 대구 8개 구·군 법정동 코드 기준정보 저장
2) 최근 12개월 매매·전월세 자료 수집
3) 대구시 단지별 미분양 파일 수집
4) 주소·단지명 표준화
5) 동일 단지 또는 인근 단지의 비슷한 전용면적 거래 추출
6) 거래유형별 시세 차이 계산
7) 출처 URL·기준일·확인일 표시.

## 6. 권장 데이터베이스
complexes: 단지 기본정보 / unsold_housing: 기준월·미분양·준공 후 미분양 / transactions: 매매·전세·월세 거래 / data_refresh_logs: 수집기간·성공일·건수·오류.

## 7. 갱신 주기
실거래가는 매일 또는 주 1회, 미분양은 월 1회, 정책·임대공고는 변경 감지 시, 단지 기본정보는 월 1회 갱신하는 구조가 적절하다. 아직 자동 수집 서버를 실행하지 않았다면 “매일 갱신”으로 단정하지 않는다.

## 8. 반드시 분리할 정보
미분양 현황은 공개 집계자료, 실거래가는 신고된 과거 거래가격, 현재 모집·분양 상태는 현재 계약 가능 여부다. 실거래가만으로 현재 미분양 잔여 세대나 현재 판매가를 확정할 수 없다.

## 9. 전세사기 수치 상태
이번 심화 조사에서 대구의 피해 건수·피해액·다세대·빌라 비중을 확정할 공식 원문 수치는 확보하지 못했다. HUG·국토교통부·대구시의 공식 통계 원문을 확인하기 전에는 숫자를 사용하지 않는다. 공공·리츠 임대가 “안전 보장”된다고 단정하지 않고, 임대인 성격과 보증제도 가입 가능 여부를 별도 확인한다.

## 10. 직접 받아 보기 체크
확인: 대구 미분양 파일데이터 존재, 총괄·구군별·단지별 구분, 매매 API, 전월세 API, 조회키 구조. 미실행: API 인증키 발급, 대구 달서구 최근 한 달 CSV 저장, 자동 갱신 서버 실행, API 이용조건·호출한도 최종 검수.

## 11. 발표용 결론
방봄은 대구시 공동주택 미분양 파일데이터와 국토교통부 아파트 매매·전월세 실거래가 API를 연결해 단지별 미분양 현황과 최근 시세를 정기적으로 갱신할 수 있다. 현재는 공공 데이터 기반의 갱신 구조와 출처를 확인한 단계이며, 실제 API 수집·자동화 전에는 “공공 데이터 10종을 매일 갱신한다”고 표현하지 않는다.

## 발표용 표현 가이드
- 정확한 표현: 공개 데이터 기반으로 정기 갱신 가능한 구조를 확인했다.
- 아직 사용하지 않을 표현: 공공 데이터 10종을 매일 갱신한다.
- 이유: 실제 API 키 발급·CSV 수집·자동화 실행이 아직 확인되지 않았기 때문이다.
