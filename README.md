# 방봄 (방봄 화면 + 방꾸미 2.0)

방 크기와 가구를 넣으면 2D 평면도와 3D로 배치를 보여 주고, 무엇이 문제인지와 어떻게 고치면 좋은지를 글로 알려 주는 방 꾸미기 웹앱이에요.
점수는 매기지 않아요. 확실한 문제, 개선 제안, 취향별 배치안 세 가지로 알려 줘요.

## 합친 구조 (2026-11-26)

사이트 이름은 방봄이에요. 프론트엔드 담당이 만든 방봄 화면과 방꾸미, 상담 AI를 한 사이트로 합쳤어요.

| 주소 | 무엇 | 어디에 있나 |
| :-- | :-- | :-- |
| `/` | 방봄: 홈, 조건 입력, 미분양 지도, 단지 카드, 24시간 상담, 이용 안내 | 원본은 `bangbom/src/`, 만든 결과는 `public/index.html` |
| `/#house` | 집 보기: 방을 고르면 방꾸미 화면이 그 방 크기와 문·창문으로 열려요 | `bangbom/src/shell/app_bb.js`의 `House` |
| `/room.html` | 방꾸미: 2D·3D 배치, 문제와 제안, 배치안, 비용, 리포트, 3D 눈높이 보기(아이 90cm·어른 160cm) | `src/` |
| `/api/consult` | 상담: 규칙이 만든 답을 AI가 쉬운 말로 풀어 써요 | `api/consult.js` |

합칠 때 지킨 규칙은 세 가지예요. 겹치는 기능은 방꾸미 것을 쓰고, 겹치지 않는 기능은 그대로 합치고, 디자인은 방봄 규칙(`docs/reference/BANGBOM_DESIGN_RULES.md`)을 따라요.

방봄 화면을 고칠 때는 `bangbom/src/` 안의 파일을 고친 뒤 `npm run bangbom`을 실행해요(파이썬 3이 필요해요). 그러면 `bangbom/index.html`이 다시 만들어지고 `public/`으로 옮겨져요. `public/index.html`을 직접 고치면 다음에 덮어써져요.

## 휴대폰에서 보기

세로로 든 휴대폰(390×844, 360×740)에 맞춰 다듬었어요. PC 화면은 전과 같아요.

- 스크롤이 긴 곳은 **카테고리 칩**으로 나눴어요. 칩을 누르면 그 항목만 보여요. 홈은 숫자·평면·돕는 방법·우리 이야기, 이용 안내는 다섯 걸음·자주 묻는 질문이에요.
- 조건 입력은 세 걸음(기본 정보 → 주거 상황 → 예산·시설)이고, 단지 카드는 아래에서 올라오는 시트예요.
- 집 보기는 화면을 통째로 써요. 위에는 "← 지도로", 단지 이름, "상담", 방 고르기 칩만 있어요.
- 3D에서 [아이 눈높이]를 누르면 방 안에 서서 90cm 높이로 봐요. 끌면 둘러보고, 바닥을 누르면 그 자리로 걸어가요. 아이 얼굴 높이에 오는 가구 모서리는 빨간 점으로 짚어 줘요. 눈높이와 빨간 점은 참고값이에요(법적·안전 기준 아님). 홈의 "아이 눈높이 90cm로 보기 →"를 누르면 바로 이 화면으로 가요.
- 확인은 PC의 브라우저에서 휴대폰 크기와 터치를 흉내 내어 했어요. 아이폰 사파리와 실제 기기에서는 따로 확인해야 해요.

## 실행 방법

Node 26이 필요해요. 프로젝트 폴더에서 터미널을 열고 아래 명령을 써요.

| 하고 싶은 일 | 명령 | 설명 |
| :-- | :-- | :-- |
| 처음 한 번 준비 | `npm install` | 필요한 도구를 내려받아요 |
| 개발하면서 보기 | `npm run dev` | <http://localhost:5180/> 이 방봄 화면(첫 화면)이고, 방꾸미 화면은 <http://localhost:5180/room.html> 이에요. 고치면 바로 반영돼요(방봄 화면은 `npm run bangbom` 뒤에 새로 고침) |
| 방봄 화면 다시 만들기 | `npm run bangbom` | `bangbom/src/`를 고친 뒤에 써요. 결과를 `public/`으로 옮겨요 |
| 계산이 맞는지 검사 | `npm test` | 배치·검사·비용 계산을 자동으로 확인해요 |
| 배포용으로 만들기 | `npm run build` | 타입 검사를 하고 `dist/` 폴더에 결과를 만들어요 |
| 이 PC를 서버로 쓰기 | `npm run serve` | 빌드한 결과를 4180번 포트로 열어요. 같은 와이파이의 휴대폰에서 `http://<이 PC의 IP>:4180` 으로 볼 수 있어요 |
| 올리기 전 한 번에 확인 | `npm run verify` | 검사 → 빌드 → 비밀값 검사를 차례로 해요 |

`npm run serve`는 먼저 `npm run build`를 한 뒤에 써요.

### 눌러 보는 검사

실제 브라우저(설치된 Edge나 Chrome을 화면 없이 띄워요)로 단추를 눌러 보는 검사예요. 새 도구를 설치하지 않아요. 먼저 `npm run build`와 `npm run serve`로 4180번을 켜 두고 다른 터미널에서 돌려요.

| 검사 | 명령 | 무엇을 보나 |
| :-- | :-- | :-- |
| 방꾸미 화면 | `node scripts/e2e-smoke.mjs` | 가구 끌기, 실행취소, 배치안, 피드백, 비용, 3D, 휴대폰 시트와 칩 (PC 1280×800 + 휴대폰 390×844) |
| 방봄 화면 | `node scripts/e2e-bangbom.mjs` | 조건 입력 세 걸음, 지도, 단지 카드 칩, 집 보기, 상담 서랍, 홈의 눈높이 링크 → 3D 아이 눈높이 (PC 1440×900 + 휴대폰 390×844·360×740) |

- 주소를 뒤에 쓰면 그 주소를 봐요(예: `node scripts/e2e-bangbom.mjs http://localhost:5180`).
- AI 호출을 아끼려면 방꾸미 검사 앞에 `E2E_NO_AI=1`을 붙여요(AI 주소를 막고 기본 답으로 봐요). 방봄 검사는 `--ai`를 줄 때만 상담에 실제 질문을 한 번 보내요.
- 하나라도 실패하면 종료 코드가 1이에요. 휴대폰은 크기와 터치를 흉내 낸 것이라 사파리와 실제 기기는 따로 봐야 해요.

## 폴더 안내

| 폴더·파일 | 들어 있는 것 |
| :-- | :-- |
| `src/components/` | 화면 틀과 패널 (방, 스타일, 가구, 배치, 비용, 리포트) |
| `src/canvas2d/` | 2D 평면도 편집기 |
| `src/canvas3d/` | 3D 보기 (필요할 때만 불러와요). 둘러보기와 눈높이 보기(아이·어른) |
| `src/engine/` | 좌표·겹침·통로·비용, 눈높이 보기의 서는 자리·걷는 길·빨간 점을 계산하는 코드. AI가 아니라 코드가 계산해요 |
| `src/data/` | 가구 카탈로그, 스타일, 예시 방, 화면 문구 |
| `src/state/`, `src/lib/` | 앱 상태·실행취소·자동 저장, 서버 호출 |
| `src/types/schema.ts` | 자료 모양(타입). `SCHEMA.md`를 옮긴 것이에요 |
| `api/` | Vercel 서버 함수. AI를 부르는 곳은 여기뿐이에요 |
| `server/` | 서버 함수들이 같이 쓰는 도우미 |
| `tests/` | 자동 검사 |
| `scripts/` | 비밀값 검사(`check-dist.mjs`), 보고서 PDF 만들기(`make-report.mjs`), 방봄 화면 옮기기(`sync-bangbom.mjs`), 눌러 보는 검사(`e2e-smoke.mjs`, `e2e-bangbom.mjs`) |
| `bangbom/` | 방봄 화면 원본(`bangbom/src/`)과 만든 결과. 휴대폰용 모양은 `bangbom/src/shell/mobile_home.css`, `mobile_app.css`에 있어요 |
| `reports/` | 작업 보고서와 PDF |
| `docs/` | 구조 약속(`ARCHITECTURE.md`), 결정 기록(`DECISIONS.md`), 참고 문서 |

규칙 문서는 이 순서로 보면 돼요: `CLAUDE.md`(꼭 지킬 원칙) → `SPEC.md`(기능) → `SCHEMA.md`(자료 모양) → `docs/ARCHITECTURE.md`(파일과 함수 약속).

## AI 키는 이렇게 써요

- AI 키가 없어도 앱은 다 돌아가요. 그때는 AI 대신 규칙으로 만든 기본 답이 나와요.
- 키는 **서버에서만** 읽어요. 이름은 `ANTHROPIC_API_KEY`예요. 어떤 값이 있는지는 `.env.example`에 적혀 있어요.
- 다른 주소의 화면에서 이 서버를 부르게 하려면 서버 환경변수 `ALLOWED_ORIGINS`에 그 주소를 쉼표로 이어 적어요(예: `https://example.com`). 적지 않으면 사이트 자신, 내 PC(localhost), 휴대폰 앱에서만 부를 수 있어요. 한 주소가 AI를 10분에 30번 넘게 부르면 규칙으로 만든 기본 답이 나와요.
- 내 PC에서 써 보려면 `.env.example`을 복사해 `.env.local`을 만들고 값을 넣어요. 이 파일은 Git에 올라가지 않아요.
- 공개 사이트에서는 Vercel의 Project Settings > Environment Variables에 넣고 다시 배포해요.
- **`VITE_`로 시작하는 이름에는 키를 절대 넣지 않아요.** `VITE_`가 붙은 값은 브라우저로 그대로 나가서 누구나 볼 수 있어요.
- `npm run check:dist`가 빌드 결과에 키나 개인 경로가 섞였는지 검사해요.
- 키가 새지 않게 지키는 장치, 첫 커밋 전에 할 일(`npm run hooks`), 소스를 안전하게 보내는 법(`npm run pack`), 키 바꾸는 순서는 [`docs/SECURITY.md`](docs/SECURITY.md)에 있어요.

## 인터넷에 올리기 (배포)

```bash
npm run verify       # 검사, 빌드, 비밀값 검사
npx vercel --prod    # Vercel에 올리기
```

처음 실행하면 Vercel 로그인과 프로젝트 연결을 물어봐요. 방꾸미 2.0은 **새 프로젝트, 새 주소**로 올려요(1.0의 저장소와 주소는 다시 쓰지 않아요).
올린 뒤에는 `https://<공개 주소>/api/health` 를 열어 `{"status":"ok"}`가 나오는지 확인해요.

## 보고서는 어디에

큰 작업을 끝낼 때마다 `reports/<이름>.md`에 보고서를 쓰고 PDF로 만들어요.

```bash
npm run report -- reports/<이름>.md
```

PDF는 `reports/pdf/<이름>.pdf`에 생겨요. 쓰는 법과 예시는 `reports/README.md`와 `reports/sample/sample.md`에 있어요.
