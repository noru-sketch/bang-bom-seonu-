## 한눈에 보기

- 목적은 **따로 만든 조각 8개를 하나로 합치고**, **새 공개 주소에 올려 실제로 열리는지 보는 것**이었어요.
- 합친 뒤 자동 검사 126개가 모두 통과했어요. 빌드(올릴 파일로 묶는 작업)와 비밀값 검사도 통과했어요.
- 합치면서 고친 것은 세 가지뿐이에요. 예시 방 옷장 위치, PC 화면의 피드백 위치, 통합 검사 5개 추가예요.
- 2026-11-26 16:26에 `https://bangkkumi2.vercel.app`에 올렸고, 공개 주소에서 서버 응답을 확인했어요.
- **화면이 뜨는 것까지만** 확인했어요. 눌러 쓰는 동작은 아직 눌러 보지 않았고, AI는 키가 없어 기본 답만 나와요.

> **공개 주소에서 확인한 서버 응답**
> - 글로 가구 추가(`/api/furniture`)에 '슈퍼싱글 침대, 1200 책상'을 보내면 침대(110×200×45cm, 시연용 예상 가격 320,000원)와 책상(120×60×72cm, 90,000원)이 돌아와요. AI가 아니라 규칙으로 만든 기본 답이에요.
> - 스타일 요청은 기본 프리셋(미리 정해 둔 색·재질 묶음, 이번에는 '웜 미니멀')과 '규칙으로 만든 기본 답이에요 (AI 연결 안 됨)' 안내가 돌아와요.
> - 잘못된 방식(GET)으로 부르면 거절(405)해요.
> - 다른 주소에서 오는 요청의 사전 확인(OPTIONS)에는 허용 응답(204)과 허용 헤더가 돌아와요.

통합 검사 5개는 이것을 확인해요. 예시 방에 확실한 문제 0건, 배치안 5개가 서로 다름, 배치안을 각각 적용한 뒤에도 확실한 문제 0건, 가구를 새로 놓아도 겹침 0건, 기본 답이 실제 검사 결과를 받아 동작.

검사 수는 이렇게 늘었어요. 합치기 전에는 121개 중 120개 통과에 보류 1개였어요. 보류였던 '예시 방 확실한 문제 0건' 검사가 옷장을 옮긴 뒤 통과했고, 통합 검사 5개를 더해 126개가 됐어요.

예시 방 화면에는 확실한 문제 없음, 개선 제안 1개(침대 머리가 창문 아래), 좋은 점 3개가 보였어요. 개선 제안은 참고용 팁이라 그대로 뒀어요.

## 중요한 결정과 이유

**1. 검사 규칙은 그대로 두고 예시 자료를 고쳤어요.**
예시 방의 옷장이 침대 앞 사용 공간을 5cm 침범해서 첫 화면에 '확실한 문제'가 떴어요. 규칙을 느슨하게 하면 문제가 사라지지만, 그러면 실제 사용자의 방에서도 같은 문제를 놓쳐요. 그래서 그 방법은 쓰지 않고 옷장을 10cm 옮겼어요. 이 문제는 검사 담당과 배치 담당이 각자 따로 발견해 같은 수치로 보고했어요.

**2. 피드백을 배치안보다 위에 뒀어요.**
방꾸미는 점수 대신 '확실한 문제 / 개선 제안 / 좋은 점'을 글로 알려 주는 것이 중심이에요. 그런데 배치안 카드 5개에 밀려 피드백이 스크롤해야만 보였어요. 순서만 바꿨고 모양과 색은 그대로예요.

**3. 3D 코드는 따로 나뉘어 있어서 3D를 열 때만 받아요.**
3D 코드(약 581kB)가 첫 화면 코드(약 362kB)보다 커요. 한 덩어리로 묶으면 3D를 안 쓰는 사람도 전부 받아야 해요. 나누기는 앞 단계에서 정했고, 이번 빌드에서 두 파일로 나뉜 것을 확인했어요.

**4. 버전은 하나만 있어요.**
개발 PC 전용 버전을 따로 만들지 않았어요. 공개 주소와 개발 PC가 같은 코드로 돌고, 서버 함수도 개발 PC에서 같은 파일을 그대로 불러요(`npm run serve`). 버전이 둘이면 "PC에서는 되는데 공개 주소에서는 안 되는" 일이 생기기 쉬워서예요.

**5. AI 키가 없다는 것을 숨기지 않아요.**
지금은 AI 키가 없어 모든 AI 답이 규칙으로 만든 기본 답이에요. 상태 확인 주소가 'AI 연결 안 됨'을 그대로 알려 주고, 서버가 보내는 기본 답에는 '규칙으로 만든 기본 답이에요 (AI 연결 안 됨)'이라는 안내가 붙어요. AI인 척하는 답은 만들지 않았어요.

**6. 지금은 PC에서 Vercel로 직접 올려요.**
Vercel은 웹사이트를 올려 주는 서비스예요. 저장소 커밋(코드 변경 기록 남기기)과 깃허브 연결은 아직 하지 않았어요. 그래서 지금은 코드를 고칠 때마다 PC에서 다시 올려야 공개 주소에 반영돼요.

## 심사위원 예상 질문과 답

**Q1. 지금 공개 주소에서 실제로 되는 것은 무엇인가요?**
저희는 `https://bangkkumi2.vercel.app`에 올려서 시작 화면, 예시 방 2D 화면, 3D 화면이 뜨는 것을 캡처로 확인했어요. 서버도 응답하고, 글로 가구 추가 주소에 문장을 보내면 규칙으로 만든 기본 답이 돌아와요. 다만 가구 끌기나 배치안 적용처럼 눌러 쓰는 동작은 아직 브라우저에서 눌러 보지 않았어요. 그건 다음 단계에서 확인해요.

**Q2. AI는 실제로 동작하나요?**
아직 아니에요. 저희는 AI 키를 아직 연결하지 않아서 지금 나오는 답은 모두 규칙으로 만든 기본 답이에요. 서버가 'AI 연결 안 됨'이라고 그대로 알려 주게 했어요. 실제 AI 호출은 한 번도 해 보지 않았기 때문에, 키를 넣은 뒤 따로 확인해야 해요.

**Q3. 자동 검사 126개는 무엇을 확인하나요?**
겹침 계산, 배치 검사, 배치안 만들기, 비용 계산, 서버 응답 같은 계산과 규칙을 확인해요. 저희는 이번에 통합 검사 5개를 더했는데, 예를 들어 배치안 5개를 각각 적용해도 확실한 문제가 0건인지 봐요. 다만 이 검사는 계산을 보는 것이고, 화면에서 버튼을 눌렀을 때의 동작까지 확인해 주지는 않아요.

**Q4. 예시 방에서 문제가 나왔을 때 왜 검사 규칙이 아니라 예시를 고쳤나요?**
옷장이 침대 앞 사용 공간을 5cm 침범한 것이 사실이었기 때문이에요. 규칙을 느슨하게 하면 예시는 깨끗해 보이지만 실제 방에서 같은 문제를 놓치게 돼요. 그래서 저희는 규칙은 그대로 두고 옷장을 10cm 옮겼어요.

**Q5. 휴대폰에서도 되나요?**
저희는 PC에서 화면을 휴대폰 크기(390×844)로 줄여 캡처해서 가로로 넘치는 곳이 없는 것을 확인했어요. 실제 휴대폰에서는 아직 열어 보지 않았어요. 좁은 가구의 이름표가 잘리는 문제도 찾아서 다음 단계에 고칠 목록에 넣었어요.

**Q6. API 키 같은 비밀값이 새지 않는다는 것을 어떻게 확인했나요?**
저희는 올리기 전에 올릴 파일을 자동으로 살펴보는 검사를 돌려요. 이번에는 글자 파일 7개를 확인했고 API 키나 개인 경로가 0건이었어요. 그리고 지금은 AI 키 자체를 아직 넣지 않았어요. 나중에 넣을 때도 브라우저 쪽 코드가 아니라 서버 쪽 설정에만 넣을 계획이에요.

**Q7. 이 단계에서 찾은 문제는 무엇이고 어떻게 했나요?**
저희는 도움말 카드가 평면도 일부를 가리는 것, 배치안 목록이 두 번 보이는 것, 휴대폰 폭에서 이름표가 잘리는 것을 찾았고 다음 단계에서 고쳐요. 가구를 전부 손으로 옮기면 배치안이 1개만 나올 수 있던 문제는 코드에서 고쳤어요. 다만 올린 뒤에 고쳐서 공개 주소에는 아직 반영되지 않았어요.

## 아직 안 된 것과 다음 단계

**아직 확인하지 못한 것**

- 눌러 쓰는 동작 전부: 가구 끌기, 크기 조절, 배치안 적용, 실행취소, AI 해설 버튼, 인쇄, 공유. 화면이 뜨는 것만 캡처로 봤어요. 5단계에서 브라우저로 눌러 봐요.
- 실제 AI 호출(키가 없어 한 번도 부르지 않음)과 실제 휴대폰(휴대폰 폭 화면은 개발 PC에서만 봄).
- 실제 그래픽카드에서의 3D. 3D는 그래픽카드 없이 소프트웨어 방식으로만 그려 봤어요.
- 리포트 탭과 스타일 탭 화면, 브라우저 콘솔(오류가 찍히는 창)은 이번에 보지 못했어요.

**알게 된 문제 (다음 단계에서 고칠 것)**

- 첫 방문 도움말 카드가 평면도 아래쪽과 3D 화질 버튼을 가려요. 닫으면 다시 나오지 않아요.
- PC에서 배치 탭을 열면 배치안 목록이 두 번 보여요. 동작에는 문제가 없어요.
- 휴대폰 폭에서 좁은 가구의 이름표가 잘려요.
- 3D 코드를 한 번 못 받으면 새로고침하기 전까지 3D가 다시 열리지 않아요.

**코드에서는 고쳤지만 공개 주소에는 아직 없는 것**

- 가구를 전부 손으로 옮긴 뒤 [전체 다시 추천]을 누르면 배치안이 1개만 나올 수 있었어요. 배치안을 만들 때는 손으로 옮긴 표시를 무시하도록 `src/state/store.ts`를 고쳤어요.
- 이 수정은 올린 뒤에 한 것이라 지금 공개 주소의 코드에는 없어요. 다시 올려야 반영돼요.
- 이 수정만 따로 확인하는 자동 검사는 아직 없고, 화면에서 눌러 보지도 않았어요.

**아직 안 된 것**

- AI API 키 연결, 저장소 커밋과 깃허브 연결, 휴대폰 앱.

**실행 방법**

```bash
npm install
npm run verify   # 자동 검사 + 빌드 + 비밀값 검사
npm run serve    # 빌드한 결과를 PC에서 열기 (포트 4180)
```

**다음 할 일 3개**

1. 브라우저에서 눌러 쓰는 동작을 하나씩 눌러 확인해요(5단계).
2. 위에 적은 문제 네 가지를 고치고, 배치안 수정까지 넣어 공개 주소에 다시 올려요.
3. AI 키를 서버 설정에 넣고 실제 AI 답을 확인해요.

## 용어 풀이

- **자동 검사(테스트)**: 계산 결과가 맞는지 컴퓨터가 대신 확인해 주는 작은 프로그램.
- **타입 검사**: 숫자 자리에 글자를 넣는 것 같은 값 종류 실수를 실행 전에 잡는 검사.
- **빌드**: 코드를 브라우저가 빨리 받을 수 있는 파일로 묶는 작업.
- **kB, 압축**: kB는 파일 크기 단위예요. 압축은 보낼 때 크기를 줄이는 것이에요.
- **API 키**: AI 서비스를 쓸 때 필요한 비밀번호 같은 값. 밖으로 새면 안 돼요.
- **Vercel**: 웹사이트를 인터넷에 올려 주는 서비스.
- **서버 함수**: 브라우저가 아니라 서버에서 도는 작은 프로그램. AI 키는 여기서만 써요.
- **응답 번호**: 서버가 답에 붙이는 번호. 200은 정상, 204는 내용 없이 허용, 405는 허용하지 않는 방식.
- **GET, OPTIONS**: 서버를 부르는 방식의 이름. OPTIONS는 본 요청 전에 먼저 묻는 사전 확인이에요.
- **규칙 기반 기본 답**: AI 없이 미리 정한 규칙과 가구 목록으로 만든 답.
- **미리보기 서버**: 빌드한 결과를 개발 PC에서 열어 보는 임시 서버.
- **소프트웨어 방식 3D**: 그래픽카드 없이 계산만으로 3D를 그리는 방식. 실제 기기와 결과가 다를 수 있어요.
- **커밋, 깃허브**: 커밋은 코드 변경을 기록으로 남기는 것, 깃허브는 그 기록을 올려 두는 사이트예요.
