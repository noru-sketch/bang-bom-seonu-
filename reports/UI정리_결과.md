# UI 정리 결과 (2026-11-27, 브랜치 hyewon-main)

맡은 범위는 화면(UI)이에요. 판정·데이터 파일(`engine.js`·`data.js`·`data2.js`·`unsold_list.js`)은 한 줄도 바꾸지 않았고, 판정 값은 기존 함수를 불러서만 썼어요. 작업마다 따로 커밋하고 바로 push했어요. `main`·`hyewon` 브랜치에는 push하지 않았고, `--force`·`--no-verify`도 쓰지 않았어요. `.env`는 열지 않았어요.

### 0. 홈의 모든 화면을 PC 한 화면 높이 안에 (원래 0번과 8번을 대신함)
- PC(901px 이상)에서 홈의 각 화면(`.hs`)은 `min-height:100vh; height:100dvh`예요. 여백·제목·큰 숫자·그림 높이는 `clamp(… vh …)`로 줄어들고, 홈의 글자는 13px 밑으로 내려가지 않아요.
- 해결 2를 세 화면으로 나눴어요: ① 지도 영상 `data-hs="지도"` ② 평면도→3D→방 + 아이 눈높이 링크 `"평면도·3D"` ③ 가구 전후 비교 `"가구 놓기"`. Solution 02 큰 제목은 ①에만 있고, ②③은 작은 소제목이에요. 오른쪽 섹션 점은 8개(7화면 + 끝)예요.
- 문제 화면의 출처는 "출처 보기 ①~⑥"으로 접었어요. 펼치면 위로 떠서 열리고 링크·기준일은 그대로예요.
- 시작하기 카드 그림 위의 10px "© OpenStreetMap" 표시는 카드 아래 안내 줄(13px)로 옮겼어요.
- 풀페이지 스크롤에서 화면 안 스크롤 로직(`SLACK`·`inner`·`gestureAt`)을 지웠어요. 이제 휠·키·밀기 한 번에 한 화면이에요.

## 0곳일 때 계산 방식 (`app_bb.js`의 `openHints`)
요건 충족 단지가 0곳이면 판정 결과 아래 "이렇게 하면 열려요" 칸을 보여 줘요. 모두 engine의 `profileResult`·`evaluate`를 **조건만 바꿔 다시 불러** 계산했고, engine 파일은 고치지 않았어요.

1. **월 예산 +10만 / +20만:** `monthly_budget`만 바꿔 8곳을 다시 판정하고, 요건 충족이 1곳 이상이면 "요건 충족 단지가 N곳이 돼요"를 보여 줘요.
2. **지금 요건 충족인 대출:** `profileResult`에서 요건 충족인 대출(예: 청년전용 버팀목)마다, 그 대출을 계산에 쓰고(`chosen.used`) 불이 꺼지지 않은 단지를 찾아 이름을 보여 줘요.
3. **모자란 돈:** 자기자금이 모자란 단지 중 모자란 금액(`shortfall`)이 가장 작은 곳에 그만큼 모은 돈을 더해 다시 판정해요. 불이 켜지면 "○○이 요건 충족이 돼요", 아니면 "자기자금이 맞아요. 그때 월 부담은 약 X만 원이에요(지금 월 예산 Y만 원)"를 보여 줘요.
4. 숫자가 안 나오는 줄은 빼고, 줄이 하나도 없으면 칸을 숨겨요.

예: "모은 돈이 부족할 때"(250만 / 1,000만 / 월 예산 60만)는 1·2번이 0곳이라 숨겨지고, 3번만 나와요. "모은 돈이 500만 원 더 있으면 월성 든든하우스의 자기자금이 맞아요. 그때 월 부담은 약 65.6만 원이에요(지금 월 예산 60만 원)."
