## 한눈에 보기

- 이 단계는 방꾸미 사이트가 아니라, 해커톤 팀 프로젝트 **'온라인 모델하우스 v3.1'의 백엔드**(화면 뒤에서 계산하고 자료를 내어 주는 서버 쪽 프로그램)를 만든 단계예요. 별도 폴더(`modelhouse_v3/backend`)에 만들었어요.
- 서버가 답하는 **주소 15개**를 만들었어요. 조건에 맞는 단지 판정과 월 부담 계산, 주변 시설 평가, 상담 기본 답, 방·가구·배치 자료, 3D 모델 목록, 디자인 값, 운영자용 대시보드 요약이에요.
- **자동 검사 129개가 모두 통과**했어요(보고서를 쓰면서 복사본에서 한 번 더 돌려 확인했어요). 팀 문서의 예시 조건으로 단지 8곳이 켜짐 3 · 깜빡임 2 · 꺼짐 3으로 나와 문서의 기대와 같았어요.
- 검증 담당이 서버 코드를 보지 않고 규칙 파일만으로 단지 4곳의 월 부담을 따로 계산했고, 서버 결과와 소수 첫째 자리까지 같았어요.
- 아직 **화면(프론트엔드)과 실제로 연결해 본 적은 없어요.** 3D 모델 파일도 아직 없고, 주변 시설·방·가구·대시보드 통계는 모두 샘플이에요.

## 무엇을 했고 왜 했나

기준 문서는 팀의 v3.1 지시서, 에셋·대시보드 명세, 주소 명세(`docs/API_SPEC.md`)예요. 기술은 파이썬 FastAPI, SQLite, pytest를 썼어요. 팀 문서가 백엔드를 FastAPI로 정해 두었기 때문이에요.

| :-- | :-- | :-- |

> **검증 단계에서 찾아 고친 문제 4건**
> 1. 무한대나 너무 큰 숫자를 보내면 서버 오류(500)가 났어요. 지금은 "입력이 잘못됐어요"(422)로 답해요.
> 2. 주변 시설 자료 파일이 없으면 여러 주소가 한꺼번에 오류가 났어요. 지금은 빈 목록으로 두고 계속 답해요.
> 3. 아주 긴 상담 글을 보내면 오류 응답이 그 글을 통째로 되돌려 주었어요. 지금은 되돌려 주지 않아요.
> 4. 상담이 범위 밖 조건(예: 나이 5세)을 검사 없이 판정에 썼어요. 지금은 판정하지 않고 일반 안내로 답해요.

## 중요한 결정과 이유

- **방꾸미 폴더와 분리했어요.** 온라인 모델하우스는 방꾸미와 다른 서비스이고 기술도 달라요(방꾸미는 자바스크립트, 이쪽은 파이썬). 코드와 자료가 섞이지 않게 별도 폴더에 두었어요.
- **팀 문서가 정한 기술(FastAPI)을 그대로 썼어요.** 주소와 칸 이름도 팀 문서(`docs/API_SPEC.md`)를 따랐어요. 화면과 서버를 따로 만들고 나중에 합치기 때문에, 문서와 다르게 만들면 합칠 때 어긋나요.
- **숫자를 지어내지 않고, 없는 값은 비웠어요.** 대시보드의 절감액, 공급유형별 이용 수, 단지별 클릭 수는 근거 자료가 없어서 빈 값과 이유 문장을 함께 보내요. 샘플 자료에는 응답에 샘플 표시를 붙였어요.
- **판정은 AI가 아니라 규칙 파일과 코드가 하고, 표현은 '요건 충족 / 확인 필요 / 미충족'만 써요.** 같은 입력이면 항상 같은 답이 나오고, 최종 결정은 은행과 기관이 하기 때문이에요. '대출 가능' 같은 단정 표현은 실제 서버 응답에서 0건임을 확인했어요.
- **받은 참고 구현 파일은 실행하지 않고 글로 읽어서 옮겼어요.** 받은 압축 파일을 그대로 실행하지 않는다는 안전 원칙 때문이에요. 대신 그 파일의 출력과 직접 맞춰 보지는 못해서, 규칙 파일로 따로 손 계산해 확인했어요.
- **3D 모델은 '상자 먼저, 나중에 교체' 방식으로 했어요.** 모델 파일을 기다리면 화면 작업이 멈춰요. 파일이 오면 파일 복사와 SQL 명령 하나로 바꾸고 코드는 고치지 않아요.
- **입력 범위를 정했어요.** 나이는 19~70세(팀 문서 값), 금액은 0 이상 1,000억 원 이하, 상담 글은 500자까지예요. 금액 상한과 500자는 팀 문서에 없어 안전장치로 정한 값이라, 화면 입력 칸과 맞는지 확인이 필요해요.

## 심사위원 예상 질문과 답

**Q1. 이 단계에서 만든 것이 정확히 무엇인가요?**
저희는 '온라인 모델하우스'의 서버 쪽 프로그램을 만들었어요. 화면이 "이 조건이면 어떤 단지를 볼 수 있어요?" 하고 물으면 서버가 규칙대로 계산해서 답해요. 주소는 15개이고, 화면은 다른 담당이 만들고 있어서 아직 합쳐 보지는 않았어요.

**Q2. 계산이 맞는지 어떻게 확인했나요?**
저희는 세 가지로 확인했어요. 자동 검사 129개가 모두 통과했어요. 팀 문서의 예시 조건(27세, 월 소득 250만 원, 자산 1,000만 원, 월 예산 60만 원)으로 켜짐 3 · 깜빡임 2 · 꺼짐 3이 나와 문서와 같았어요. 또 규칙 파일만 보고 단지 4곳을 손으로 따로 계산했는데 소수 첫째 자리까지 같았어요.

**Q3. AI가 대출이 된다고 잘못 말하면 어떻게 하나요?**
저희 서버는 지금 AI를 연결하지 않았어요. 판정과 금액은 규칙 파일과 코드가 계산하고, 상담은 미리 써 둔 틀로만 답해요. '가능합니다', '승인됩니다' 같은 말은 걸러 내요. 다만 이 거름 장치는 정해진 네 가지 말투만 잡아서, 나중에 AI를 붙이면 보강이 필요해요.

**Q4. 3D 모델이 아직 없는데 화면은 어떻게 나오나요?**
저희는 모델 파일이 없어도 치수와 색만으로 상자를 그리도록 목록을 만들었어요. 그래서 지금은 방과 가구가 전부 상자로 그려져요. 모델 파일이 오면 파일 복사와 SQL 명령 하나로 바뀌게 해 두었는데, 이 교체는 가짜 파일로만 시험했어요.

**Q5. 대시보드에 나오는 숫자는 실제 이용 기록인가요?**
아니에요. 대시보드 통계는 전부 샘플이고, 응답에도 샘플 표시가 붙어 있어요. 절감액, 공급유형별 이용 수, 단지별 클릭 수는 근거가 되는 기록이 없어서 숫자를 지어내지 않고 비워 두었어요. 실제 이용 기록을 쌓는 기능이 먼저 필요해요.

**Q6. 이상한 값을 넣으면 서버가 멈추지 않나요?**
저희는 검증 단계에서 일부러 무한대, 아주 큰 숫자, 아주 긴 글을 보내 봤어요. 그때 서버 오류가 나는 문제 등 4건을 찾아 고쳤고, 같은 문제가 다시 생기지 않게 검사 40개를 더했어요. 다만 규칙 파일이나 단지 자료 파일 자체가 없으면 판정이 동작하지 않는 점은 그대로예요.

**Q7. 문서의 기대와 다르게 나온 것은 없나요?**
한 가지 있어요. 자산을 5,000만 원으로 늘리면 켜지는 단지가 늘어난다고 문서에 적혀 있는데, 저희 결과는 켜짐 3곳 그대로였고 깜빡임이 2에서 3, 꺼짐이 3에서 2로 바뀌었어요. 계산 오류의 징후는 없지만 기획 담당의 확인이 필요해요.

## 아직 안 된 것과 다음 단계

- **화면과 연결해 보지 않았어요.** 칸 이름이 서로 맞는지, 한도를 넘는 단지(계산 내역이 빈 단지)가 화면에 잘 나오는지 확인하지 못했어요.
- **3D 모델 파일이 하나도 없어요.** 목록 13개가 모두 '준비 안 됨'이고 전부 상자로 그려져요. 방 상자 크기도 목록(8.4 × 10.0m)과 샘플 방 자료(12 × 7m)가 서로 달라요.
- **자료가 샘플이에요.** 주변 시설 10곳, 방 1개, 가구 9개, 배치 예시 1개, 대시보드 7일치 통계가 모두 샘플이에요. 단지도 8곳 중 7곳이 샘플이고, 금리와 한도는 시연용 가정값이에요.
- **주변 시설 샘플이 한 지역에만 있어요.** 그래서 먼 단지는 생활 편의 점수가 0점으로 나와요. 계산은 맞지만 자료가 없는 것이 '낮음'처럼 보여요. 시연은 시설 자료가 있는 단지로 하는 편이 안전해요.
- **지원 정보의 기준일이 비어 있어요.** 규칙 파일에 확인 날짜가 없어서예요. 시중은행 전세대출은 출처 링크도 없어요.
- **AI 상담 연결은 하지 않았어요.** 상담 기능은 팀의 다른 담당이 따로 만들고 있고, 여기 것은 임시 대체용이에요. 가구 추천과 구매 링크도 없어요.
- **문서와 다른 작은 점이 남아 있어요.** 서버 상태 확인 주소에 AI 연결 여부 칸이 없고, 추천 배치가 문서의 2~3개가 아니라 1개예요. 접속 허용 설정(CORS)도 시연용으로 모두 열어 두었어요.

**실행 방법** (`modelhouse_v3/backend` 폴더 안에서 실행해요. 자세한 내용은 그 폴더의 `README.md`에 있어요.)

```
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe db.py
.\.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
.\.venv\Scripts\python.exe -m pytest -q
```

순서대로 가상환경 만들기, 설치, DB(데이터베이스) 준비, 서버 켜기(8000번 포트), 자동 검사예요. 서버를 켜고 브라우저에서 `http://localhost:8000/docs`를 열면 주소 목록이 보여요. 검사는 `129 passed`가 정상이에요. 설치에는 인터넷이 필요하니, 발표장에는 미리 설치해 둔 상태로 가져가요.

**다음 할 일 3개**

1. 화면(프론트엔드)이 준비되면 실제로 연결해서 칸 이름과 빈 계산 내역 표시를 확인해요.
2. 기획 담당에게 '자산 5,000만 원' 결과와 기준일·출처 링크, 금액 상한 값을 확인받아요.
3. 3D 모델 파일과 실제 주변 시설 자료가 오면 샘플을 바꾸고, 방 크기와 모델 경로가 서로 맞는지 맞춰요.

## 용어 풀이

- **백엔드 / 프론트엔드**: 백엔드는 화면 뒤에서 계산하고 자료를 내어 주는 서버 쪽 프로그램, 프론트엔드는 사용자가 보는 화면 쪽 프로그램이에요.
- **API, 주소**: 화면이 서버에 물어보는 창구예요. 주소마다 하는 일이 정해져 있어요.
- **FastAPI, SQLite, SQL**: FastAPI는 파이썬으로 서버를 만드는 도구, SQLite는 파일 하나로 된 작은 데이터베이스, SQL은 데이터베이스에 내리는 명령문이에요.
- **pytest, 자동 검사, 회귀 검사**: 코드가 기대한 답을 내는지 프로그램이 대신 확인해 주는 검사예요. 회귀 검사는 고친 문제가 다시 생기지 않는지 지켜보는 자동 검사예요.
- **규칙 파일(rules.json), JSON**: 대출·지원의 나이, 소득, 한도, 금리 같은 조건을 적어 둔 파일이에요. JSON은 자료를 이름과 값의 짝으로 적는 글 형식이에요.
- **LTV**: 보증금의 몇 %까지 빌릴 수 있는지를 정하는 한도예요. 지금 규칙 파일에는 값이 비어 있어 실제 판정에는 쓰이지 않고, 켰을 때의 계산만 검사해 두었어요.
- **켜짐 / 깜빡임 / 꺼짐**: 단지 불빛으로 보여 주는 판정 결과예요. 켜짐은 예산 안에서 요건 충족, 깜빡임은 확인 필요, 꺼짐은 미충족이에요.
- **에셋 매니페스트, 디자인 토큰**: 에셋 매니페스트는 3D 모델 파일이 어디 있고 준비됐는지를 적은 목록, 디자인 토큰은 색·글꼴·여백 같은 디자인 값을 이름 붙여 모아 둔 것이에요.
- **대시보드, 500 / 422**: 대시보드는 운영자가 이용 현황을 숫자로 보는 화면이에요. 500과 422는 서버가 돌려주는 상태 번호로, 500은 서버 오류, 422는 입력이 잘못됐다는 뜻이에요.
- **가상환경, 포트, CORS**: 가상환경은 필요한 도구만 따로 설치해 두는 공간, 포트(8000번)는 한 컴퓨터 안에서 서버를 구분하는 번호, CORS는 다른 주소의 화면이 서버를 부르도록 허락하는 설정이에요.
