## 한눈에 보기

- 이 단계의 목적은 **기능 8개를 동시에 만들어도 서로 맞물리게** 하는 것이었어요. 그래서 모두가 같이 쓰는 뼈대 코드와 약속 문서를 먼저 만들었어요.
- 나온 것은 세 가지예요. 새 프로젝트와 설정, 공통 약속 파일 9개, 그리고 새 공개 주소(`https://bangkkumi2.vercel.app`)예요.
- 1.0 사용 리뷰에서 나온 불편(실행취소 없음, 가구를 추가하면 배치가 초기화됨)은 나중에 덧붙이지 않고 **바탕 설계에 처음부터** 넣었어요.
- 공개 주소에는 '곧 열려요' 화면만 올려서, 올리는 과정이 되는지 먼저 확인했어요.
- 이 단계에서는 **화면 기능을 만들지 않았어요.** 방을 그리고 가구를 놓는 기능은 다음 단계에서 만들어요.

> 응답 200은 "정상", 204는 "정상이고 돌려줄 내용은 없음"이라는 뜻이에요. 표에서 "읽어 확인", "열어 확인"이라고 쓴 것은 화면에서 눌러 본 것이 아니에요.

## 중요한 결정과 이유

**1. 기능보다 약속 문서를 먼저 썼어요.**
다음 단계에서 기능 8개(배치 검사, 자동 배치, 서버, 2D 편집, 3D 보기, 화면 틀, 패널, 문서·도구)를 동시에 만들어요. 파일 이름과 함수 모양이 미리 정해져 있어야 따로 만든 조각이 한 번에 맞아요.

**2. 좌표는 1cm 단위로 하고, 1cm 미만으로 겹친 것은 겹침으로 보지 않아요.**
1.0은 가구를 끌 때 5cm 칸에 맞춰 놓았어요. 1단계 조사에서 이 칸 때문에 가구가 3cm 겹친 채 놓이고 빨간 오류가 뜨는 것을 봤어요. 2.0은 좌표를 1cm 단위 정수로 다뤄서 딱 맞게 붙일 수 있어요. 벽이나 옆 가구에 딱 붙인 것(0cm)은 겹침이 아니에요.

**3. 실행취소 50단계를 처음부터 넣었어요.**
사용 리뷰 5번이 "단축키와 실행취소가 없다"였어요. 실행취소는 모든 편집 동작과 엮여요. 그래서 나중에 붙이면 빠지는 동작이 생기기 쉽다고 봤어요.

**4. 가구를 끄는 동작 한 번은 실행취소 한 단계로 묶어요.**
작업 기록에 따르면 1.0에서는 한 번 끌 때 기록이 수십 개 쌓였어요(이번에 1.0 코드를 다시 열어 보지는 않았어요). 2.0은 끌기 시작과 끝을 묶어 한 번만 기록하도록 코드를 짰어요.

**5. 가구를 추가해도 기존 배치는 그대로 둬요.**
사용 리뷰 6번이 "가구를 추가하면 배치가 초기화된다"였어요. 새 가구는 빈 자리를 찾아서 놓도록 정했고, 전체를 다시 추천받는 것은 따로 부르는 동작으로 나눴어요. 빈 자리를 찾는 계산 자체는 다음 단계에서 만들어요.

**6. 점수 칸을 자료에 아예 만들지 않았어요.**
방꾸미 2.0은 배치를 숫자 점수로 평가하지 않고, 문제와 제안을 글로 알려 주기로 했어요. 자료 모양에 점수 칸이 없으면 실수로 화면에 점수가 나오기 어려워요.

**7. 계산 코드는 JavaScript로 두고, 타입 검사만 함께 걸었어요.**
같은 계산 파일을 브라우저, 서버, 자동 검사가 함께 쓰도록 가장 단순한 형태로 뒀어요. 그 대신 빌드할 때 타입 검사가 이 파일들도 같이 봐요.

**8. AI 키는 서버에만 둬요.**
설정값 이름이 `VITE_`로 시작하면 그 값은 브라우저로 나가요. 그래서 그 이름에는 비밀값을 넣지 않기로 정하고, 올릴 파일에 비밀값이나 개인 경로가 섞였는지 검사하는 명령(`npm run check:dist`)을 뒀어요.

**9. 강조색은 파랑 한 가지만 써요.**
밝고 깨끗한 쇼핑앱 느낌이 목표예요. 바탕은 흰색과 따뜻한 회색이고, 문제·제안·좋은 점을 알리는 색 3가지만 따로 뒀어요. 색을 미리 정해 두면 따로 만든 화면도 한 앱처럼 보이기 쉬워요.

**10. 공개 주소를 기능보다 먼저 만들었어요.**
올리는 과정에서 생기는 문제는 기능과 상관없이 생겨요. 준비 중 화면으로 미리 올려 보면 뒤에서 시간을 덜 잃어요. 작업 기록에 따르면 요금제는 Vercel 무료(Hobby)예요.

## 심사위원 예상 질문과 답

**질문 1. 왜 기능부터 만들지 않고 바탕부터 만들었나요?**
저희는 기능 8개를 동시에 만들 계획이었어요. 파일 이름, 함수 모양, 좌표 규칙을 먼저 문서와 코드로 정해 두지 않으면 따로 만든 조각이 서로 맞지 않아요. 그래서 한 단계를 들여 공통 약속을 먼저 만들었어요.

**질문 2. 1.0의 사용 리뷰는 이 단계에 어떻게 반영됐나요?**
저희는 리뷰 5번(실행취소 없음)과 6번(가구 추가 시 배치 초기화)을 바탕 설계에 넣었어요. 실행취소는 50단계까지 기록하고, 가구 추가는 기존 가구 위치를 건드리지 않고 빈 자리를 찾도록 정했어요. 다만 이 단계에서는 규칙과 뼈대 코드를 만든 것이고, 화면에서 눌러 보는 확인은 다음 단계에서 해요.

**질문 3. 가구가 겹쳤는지는 어떻게 판단하나요?**
저희는 좌표를 1cm 단위로 다루고, 1cm 이상 겹쳐야 겹침으로 봐요. 벽이나 다른 가구에 딱 붙인 배치는 문제가 아니에요. 1.0에서는 5cm 칸 때문에 가구가 3cm 겹친 채 놓여 오류가 뜨는 일이 있어서, 2.0은 1cm 단위로 딱 맞게 놓을 수 있게 했어요.

**질문 4. 배치에 점수를 매기나요?**
저희는 점수를 매기지 않아요. 확실한 문제, 개선 제안, 좋은 점을 글로 알려 주는 방식이에요. 자료 모양을 정할 때부터 점수 칸을 넣지 않았어요.

**질문 5. AI 키 같은 비밀값은 어떻게 지키나요?**
저희는 키를 서버 쪽 환경 설정에만 두고, 브라우저로 나가는 코드에는 넣지 않아요. 키가 든 파일은 저장소에 올라가지 않게 제외했어요. 그리고 올릴 파일에 비밀값이나 개인 경로가 섞였는지 검사하는 명령을 따로 만들었어요.

**질문 6. 지금 공개 주소에 들어가면 무엇이 보이나요?**
이 단계를 마친 시점에는 '곧 열려요' 화면만 있었어요. 저희는 올리는 과정이 되는지 먼저 확인하려고 준비 중 화면으로 올려 봤어요. 첫 화면과 서버 상태 확인 주소가 모두 정상 응답했어요. 그때 공개 주소에는 AI 키를 아직 연결하지 않았어요.

**질문 7. 치수나 가격은 믿어도 되는 값인가요?**
저희는 어림값이나 참고용 값에는 고지 문구를 붙이기로 정했어요. 가격은 '시연용 예상 가격', 통로 폭 같은 기준은 '참고값 (법적·안전 기준 아님)'이라고 적어요. 이 문구는 한 파일에 모아 두고, 화면은 그 파일의 글자를 그대로 가져다 쓰기로 약속했어요.

## 아직 안 된 것과 다음 단계

아직 안 된 것:

- 공개 주소에는 준비 중 화면만 있어요. 서버 상태 확인 주소의 답을 보면 AI 키도 아직 연결되지 않았어요.
- 실행취소 50단계, 끌기 묶기, "가구를 추가해도 배치 유지"는 상태 관리 코드에 들어 있지만, 실제 화면에서 눌러 본 확인은 아직이에요.
- 이 단계에서 자동 검사로 확인한 것은 좌표 계산 파일(10개 통과)뿐이에요. 상태 관리와 저장 코드에는 자동 검사가 없어요.
- 휴대폰 앱으로 포장하는 일(Capacitor)은 중간점검 뒤에 해요.
- 이 프로젝트는 아직 커밋(변경 기록 남기기)을 하지 않았어요.
- 화면 기능(방 그리기, 가구 놓기, 3D 보기)은 이 단계에 없어요. 다음 단계에서 만들어요.

실행 방법: 프로젝트 폴더에서 `npm install`을 한 번 실행한 뒤, `npm run dev`(내 PC에서 열어 보기)나 `npm test`(자동 검사)를 실행해요.

다음 할 일 3개:

1. 약속 문서를 기준으로 기능 8개를 동시에 만들어요.
2. 만든 조각을 합쳐서 전체 검사(`npm test`, `npm run build`, `npm run check:dist`)를 통과시켜요.
3. 공개 주소의 준비 중 화면을 실제 앱으로 바꿔 올리고, 첫 커밋을 남겨요.

## 용어 풀이

- **템플릿**: 새 프로젝트를 시작할 때 쓰는 기본 틀이에요.
- **JavaScript**: 웹 브라우저에서 돌아가는 프로그래밍 언어예요.
- **React, Vite**: React는 화면을 조각으로 나눠 만드는 도구, Vite는 코드를 올릴 파일로 묶는 도구예요.
- **TypeScript, 타입 검사**: 값의 종류(숫자, 글자 등)를 적어 두고, 틀리게 쓴 곳을 실행 전에 찾는 것이에요.
- **Tailwind CSS, three.js**: 앞의 것은 색과 여백을 꾸미는 도구, 뒤의 것은 3D를 그리는 도구예요.
- **Claude SDK**: AI(Claude)에게 서버에서 질문을 보내는 도구예요.
- **자동 검사(테스트)**: 계산 결과가 맞는지 프로그램이 대신 확인해 주는 것이에요.
- **빌드, 배포**: 빌드는 코드를 올릴 수 있는 파일로 묶는 일이고, 배포는 그 파일을 공개 주소에 올리는 일이에요.
- **Vercel, 서버 함수**: Vercel은 웹사이트를 올려 주는 서비스예요. 서버 함수는 브라우저가 아니라 서버에서 돌아가는 작은 프로그램이고, AI 키는 여기서만 써요.
- **환경변수(.env)**: 키 같은 설정값을 코드 밖에 따로 적어 두는 곳이에요.
- **사전 확인(CORS preflight)**: 다른 주소에서 온 요청을 받아도 되는지 브라우저가 먼저 물어보는 절차예요.
- **상태 관리, 디자인 토큰**: 상태 관리는 지금 방과 가구의 모습을 한곳에서 기억하고 바꾸는 일이고, 디자인 토큰은 미리 이름을 붙여 둔 색과 모양 값이에요.
- **저장소**: 코드와 변경 기록을 모아 두는 곳이에요.
