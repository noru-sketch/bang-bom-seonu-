## 한눈에 보기

- 프론트엔드(사용자가 보는 화면) 담당 팀원이 만든 **방봄 화면**과 **방꾸미**(방 배치 도구), **상담 AI**를 한 사이트로 합쳤어요. 사이트 이름은 **방봄**이고, 공개 주소는 예전 그대로 `https://bangkkumi2.vercel.app` 이에요.
- 첫 화면(`/`)은 방봄이에요(홈, 조건 입력, 2.5D 미분양 지도, 단지 카드, 24시간 상담, 이용 안내). 방꾸미 편집 화면은 `/room.html`로 옮겼고, 방봄의 '집 보기'를 누르면 그 안에 열려요.
- 합칠 때 규칙 세 가지를 지켰어요. (1) 기능이 겹치면 방꾸미 것을 쓴다. (2) 겹치지 않는 기능은 그대로 합친다. (3) 디자인은 방봄을 기준으로 한다.
- 24시간 상담은 **판정은 규칙이 하고, AI는 그 결과를 쉬운 말로 풀어 쓰기만** 하게 만들었어요. AI가 안 되면 규칙이 만든 답을 그대로 보여 줘요.
- 자동 검사 **168개가 모두 통과**했어요. 방꾸미 화면을 프로그램이 실제로 눌러 보는 검사도 디자인을 바꾼 뒤 다시 돌려 **80개가 모두 통과**했어요(PC와 휴대폰 크기, 내 PC에서 빌드한 결과로). 방봄 화면도 공개 주소에서 프로그램으로 눌러 봤고, 찾은 문제를 고친 뒤 **13개 흐름이 모두 통과**했어요. 첫 배포 뒤에 고친 것들은 18시 28분까지 다시 올려 공개 주소에 반영했어요.

## 중요한 결정과 이유

- **겹치는 '집 보기'는 방꾸미로 바꿨어요.** 방봄의 원래 집 보기는 세대 전체를 3D로 보여 주고 예산에 맞춰 가구를 추천했어요. 방꾸미는 방 하나만 다루지만 문제 찾기, 배치안, 비용, 리포트, AI 해설이 있고 계산 부분에 자동 검사가 붙어 있어요. 두 가지를 다 두면 같은 일을 하는 화면이 둘이 돼서 하나로 정했어요. 대신 세대 전체 3D 조감도, '방 안' 시점, 예산 추천 탭은 빠졌어요.
- **완성 파일이 아니라 원본을 고쳤어요.** 방봄은 여러 조각 파일을 스크립트가 한 파일로 합쳐서 만들어요. 완성 파일만 고치면 프론트엔드 담당이 다음에 다시 만들 때 고친 내용이 사라져요.
- **방꾸미를 방봄 안에 '끼워 넣는' 방식으로 합쳤어요.** 방봄 화면 안에 방꾸미 화면을 창처럼 띄우고, 방 정보는 주소 뒤에 붙여 넘겨요. 두 프로그램의 코드를 섞지 않아서 서로의 검사를 깨뜨리지 않아요. 코드를 한 덩어리로 다시 짜는 방법은 시간이 많이 들고 위험해서 택하지 않았어요.
- **디자인은 값만 바꿨어요.** 방꾸미는 색과 글꼴을 한곳(`src/index.css`)에 이름 붙여 모아 두었어요. 그 값만 방봄 것으로 바꾸니 화면 전체가 따라왔고, 화면 코드를 하나하나 고치지 않았어요.
- **판정은 규칙이, 설명만 AI가 해요.** AI가 대출 가능 여부를 스스로 판단하면 틀린 말을 할 수 있어요. 그래서 판정·숫자·링크는 규칙이 만든 것을 그대로 쓰고, AI가 쓴 글에서 인터넷 주소를 지우고, '가능합니다', '승인돼요' 같은 단정 표현이 든 문장은 '최종 결정은 각 기관이 해요.'로 바꿔요. AI가 자료에 없는 숫자를 말하면 그 답은 버리고 규칙 답을 보여 줘요.
- **AI로 보내는 것을 줄였어요.** 질문과 판정 요약만 보내요. 나이·소득 같은 입력값 자체는 보내지 않고, 판정 이유 글에 들어 있는 '입력 만 N세'도 지우고 보내요. 다만 판정 요약에는 '연소득이 기준 초과' 같은 결과와 고른 단지의 월 부담 계산이 들어 있어요. 주민번호 모양이 있으면 AI로 보내지 않아요.
- **이름은 방봄, 주소는 예전 그대로예요.** 이미 알려 둔 주소를 바꾸지 않으려고요.

## 심사위원 예상 질문과 답

**Q1. 방봄과 방꾸미는 어떤 관계인가요?**

저희 사이트 이름은 방봄이에요. 방봄은 조건을 넣으면 들어갈 수 있는 단지를 지도에서 보여 주고, 단지에서 '집 보기'를 누르면 방 배치 도구인 방꾸미가 그 안에 열려요. 가구 놓기 기능이 두 곳에 겹쳐 있어서, 겹치는 부분은 방꾸미 것으로 하나만 남겼어요.

**Q2. 집 보기에 나오는 방은 실제 그 단지의 평면인가요?**

아니에요. 저희는 공고 평면도 원본을 쓰지 않고, 84㎡와 59㎡ 표준 구조를 단순하게 그린 것에서 방 하나의 크기와 문·창문 위치를 가져와요. 그래서 실제 세대와 치수가 다를 수 있어요. 거실도 실제로는 주방 쪽이 트여 있지만 지금은 네 벽이 있는 방으로 다뤄요.

**Q3. 상담은 AI가 대출이 되는지 판단해 주나요?**

아니에요. 저희는 판정을 정해 둔 규칙으로 하고, AI는 그 결과를 쉬운 말로 풀어 쓰기만 해요. AI가 '가능합니다'처럼 단정하는 문장을 쓰면 서버가 '최종 결정은 각 기관이 해요'라는 문장으로 바꿔요. 최종 판정은 은행과 기관이 한다고 화면에도 적어 두었어요.

**Q4. 제가 넣은 소득이나 나이가 AI 회사로 넘어가나요?**

입력값은 브라우저에만 저장해요. 상담에 질문할 때만 질문과 판정 요약을 AI 답변을 만드는 데 보내요. 나이·소득 숫자 자체는 보내지 않지만, '요건 충족'이나 '기준 초과' 같은 판정 결과와 월 부담 계산은 판정 요약에 들어 있어요.

**Q5. AI가 멈추면 상담이 안 되나요?**

돼요. 저희는 규칙이 먼저 답을 만들어 두고, 15초 안에 AI 답이 없거나 실패하면 그 답을 그대로 보여 줘요. 서버가 규칙 답으로 돌아가는 것은 자동 검사에 들어 있고, 15초 기다림은 브라우저 쪽이라 자동 검사에는 없어요.

**Q6. 합치면서 원래 있던 기능이 망가지지 않았는지 어떻게 확인했나요?**

예전부터 있던 방꾸미 자동 검사에 상담 검사 8개를 더해 모두 168개가 통과했어요. 방꾸미 화면을 실제로 눌러 보는 자동 검사도 마지막 판으로 다시 돌려 80개가 모두 통과했어요(PC와 휴대폰 크기, 브라우저 오류 0건). 방봄 화면은 공개 주소에서 프로그램으로 눌러 봤어요(조건 입력, 지도, 집 보기, 방 바꾸기, 저장, 상담, 뒤로 가기). 방을 바꾼 뒤 뒤로 가기를 누르면 방 단추와 내용이 어긋나는 문제가 하나 나와서 고쳤고, 다시 돌려 13개 흐름이 모두 통과했어요.

**Q7. 지도에 나오는 단지와 금액은 실제 자료인가요?**

대부분 시연용 샘플이에요. 단지 8곳 중 7곳은 이름 끝에 (샘플)이라고 표시돼 있고, 나머지 1곳만 공개 보도를 출처로 적어 넣었어요. 시설, 금리, 지원 기준도 방봄 원본에 있던 시연용 값이에요.

## 아직 안 된 것과 다음 단계

- 첫 배포(17시 51분) 뒤에 고친 것들(예전 주소 넘겨 주기, 뒤로 가기, 집 보기 안의 [처음부터], 상담 문장 다듬기)은 18시 28분까지 다시 올려 반영했어요.
- 홈의 '방 안 시점으로 보기' 링크는 '집 보기에서 가구 놓아보기'로 고쳤어요. 하지만 홈의 '아이 눈높이 90cm' 소개 글은 방봄 원본 그대로인데, 합친 사이트에는 그 시점으로 걸어 보는 기능이 없어요. 프론트엔드 담당과 문구를 정해야 해요.
- 방꾸미는 방 하나만 다뤄요. 세대 전체 3D 조감도, '방 안' 시점, 예산 추천 탭은 빠졌어요(비용은 비용 탭으로 봐요).
- 눌러 보는 자동 검사(`scripts/e2e-smoke.mjs`)는 방꾸미 화면만 봐요. 방봄 화면을 눌러 본 점검은 임시 스크립트로 돌렸고, 프로젝트의 자동 검사에는 아직 넣지 않았어요.
- 집 보기 화면에서는 24시간 상담 단추가 가려져요(받은 원본도 같았어요). 상담은 지도 화면에서 열어요.
- 6단계 백엔드(FastAPI 서버)는 공개 사이트에 연결하지 않았어요. 판정은 브라우저의 규칙 코드가 해요.
- 지도 도구(three.js)는 코드 검토 뒤 같은 사이트에서 받게 바꿨어요. 영문 글꼴만 인터넷에서 받아요.
- 방봄 `index.html`을 파일로 바로 열면 집 보기와 상담 AI는 동작하지 않아요(서버에 올려야 해요).
- 팀 사진(`img/story.jpg`)과 이사 영상(`vid/move.mp4`)이 아직 없어요(공개 주소에서 '파일 없음' 404로 응답).

**실행 방법**

```bash
npm install
npm run dev        # http://localhost:5180 (방꾸미 화면은 /room.html)
npm run bangbom    # bangbom/src 를 고친 뒤 화면을 다시 만들 때 (파이썬 3 필요)
npm test           # 자동 검사 168개
```

**다음 할 일 3개**

1. 휴대폰 실제 기기로 지도와 집 보기를 직접 확인하고, 휴대폰 집 보기에서 두 줄로 보이는 아래 메뉴(방꾸미 메뉴와 방봄 탭)를 한 줄로 정리해요.
2. 방봄 화면을 눌러 본 점검을 프로젝트의 자동 검사로 옮기고, 집 보기에서도 상담을 열 수 있게 해요.
3. 팀 사진과 이사 영상을 넣고 홈의 '아이 눈높이' 문구를 정해요. 6단계 백엔드를 연결할지도 팀에서 정해요.

## 용어 풀이

- **프론트엔드 / 백엔드**: 사용자가 보는 화면 쪽 / 화면 뒤에서 계산하는 서버 쪽 프로그램이에요.
- **서버 함수(`/api/consult`)**: 브라우저가 부르면 서버에서 실행되는 작은 프로그램이에요. AI 열쇠를 서버에만 둬요.
- **규칙(규칙 코드)**: 나이·소득 같은 조건으로 요건 충족 / 확인 필요 / 미충족을 정하는, 미리 정해 둔 계산이에요.
- **자동 검사**: 코드가 기대한 답을 내는지 프로그램이 확인하는 검사예요. 눌러 보는 자동 검사는 브라우저를 열어 단추까지 눌러 봐요.
